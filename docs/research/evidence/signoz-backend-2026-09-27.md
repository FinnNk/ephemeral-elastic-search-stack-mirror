# SigNoz backend: local verification

Measured on 27 September 2026 in the Windows x64 k3d lab. The initial transport checks preceded organisation setup; the later checks below confirm connected ingestion. They do not establish dashboard or SLO correctness.

| Check | Observation |
| --- | --- |
| Capacity | The 12 GiB `k3d-observability-0` worker used 3,028 MiB (24%) at the snapshot. The existing agent used 2,239 MiB of 4 GiB and the server 4,581 MiB of 6 GiB. Docker reported 2.959/12, 2.195/4 and 4.489/6 GiB for those containers. D: had about 249 GiB free. These are idle point measurements. |
| Backend | SigNoz chart `0.143.0` installed in `lab-observability`. SigNoz, ClickHouse, ZooKeeper, operator, collector, gateway and all three log-agent Pods reached Ready. ClickHouse, ZooKeeper and SigNoz PVCs were Bound at 20, 8 and 1 GiB. `/api/v1/health` returned HTTP 200. The worktree installer reapplied the pinned chart as Helm revision 3, then the approved account overlay as revision 4, with PVCs retained and both Collector workloads Ready. |
| Pinned inputs | Chart archive SHA-256 `e3ec7144de45404b10837ef80e86c6cec4960cde41e914f4782d9205c739adad`; gateway/log-agent image digest `fd328de2552466ad78385e1b1289c3f2402b1c45f265b252aab1955b42845ac1`. The ClickHouse UDF download passed its amd64 SHA-256 check on restart. amd64 and arm64 image manifests were checked; native Apple silicon was not. |
| Signal production | An isolated synthetic Search API probe emitted a fast HTTP 200, a 360 ms HTTP 200 and an HTTP 502 with safe trace IDs. A control-image probe emitted operation traces and metrics to a local mock receiver. The running control Pod was updated to Nexus digest `03de81893bd916d7e09d9e5c9ae21d6db31ceb7723c52d828a49a13eb9f7ddee`; the smoke check passed with 152 environment records and 43 comparison records. |
| Initial ingestion gap | Before first organisation setup, the SigNoz collector's active OpAMP config used `nop` pipelines and refused port 4317. Gateway logs showed dropped traces and metrics after bounded retries; ClickHouse trace and metric tables remained empty at that point. |
| Approved bootstrap | A random password was written only to ignored `.lab/secrets/signoz-agent-root.password` and Kubernetes Secret `lab-signoz-root`. The chart overlay created organisation `relevance-lab` and administrator `elastic-agent@lab.local`; SigNoz logged successful root-user reconciliation. The active collector then exposed OTLP and ClickHouse exporters. The human owner account remains separate and is pending an email address. |
| Connected search signals | An in-cluster probe sent three synthetic normal-cohort outcomes through the gateway: fast HTTP 200 at 80 ms, slow HTTP 200 at 360 ms and HTTP 502 at 42 ms. Each trace has `search.request`, `search.query_understanding` and `search.elasticsearch` spans in `signoz_traces.signoz_index_v3`. The maxima of stored cumulative counters in `signoz_metrics.samples_v4` were eligible 3, success-good 2 and responsive-good 1. These are storage checks, not dashboard calculations. |
| Correlated delivery signals | A running delivery watcher produced `delivery.validate_pr` and `delivery.watch_once` spans in `signoz_traces.signoz_index_v3`. Two structured events in `signoz_logs.logs_v2` carried the same trace ID, one for each operation. This establishes stored trace/log correlation; UI drill-through is still to be checked. |
| Failure isolation | With the gateway Pod absent, the control smoke check still passed. The gateway was restored and its Deployment rolled out. This checks one control operation path; it does not establish search load overhead or zero loss after recovery. |
| Alternate exporter | Pinned Collector `0.161.0` sent synthetic traces and delta metrics through the New Relic profile to a local OTLP/HTTP mock receiver using a dummy API key. No New Relic tenant was used. |
| Source checks | Focused operation/evaluator/comparison tests passed 11/11 against the worktree source using the control image's dependencies; changed Python files compiled. C4 deployment SVGs and the Archify investigation view passed rendering and visual review. |
