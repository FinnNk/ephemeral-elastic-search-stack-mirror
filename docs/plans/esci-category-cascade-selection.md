# Select a category-aware judgement cascade

Status: the CPU surveys are measured. The research-owned category study is
prepared, but its guarded GPU execution and quality results are pending.
No candidate from these surveys is active.

## Intent and constraints

Find stages that add enough accurate labels to approach 80% coverage of the
retained Search API comparison. Start with the matched category study, then
spend further compute only on a measured signal. Published labels remain
authoritative; a later stage sees only gaps left by earlier qualified stages.

- Keep the 80% gate and existing label-quality requirements. A temporary
  exception requires a recorded human decision.
- Protect the research process's unsaved predictions. Start at a completed,
  saved classifier boundary with its owner's exclusive GPU guard.
- Keep the original and fresh confirmation reservations, specialist queries,
  official test and the complete 1,000-query fitting pool out of adaptive work.
- Freeze input fields, prompts, weights, score mapping and thresholds before
  their assessment. A changed category contract is a new candidate.
- Keep CPU screens, published-reference confirmation and independently blinded
  actual-gap assessment distinct. Model agreement does not replace references.
- Retain failed attempts and exact executed sources. Do not alter deployed
  defaults or add compatibility adapters for experimental data.

## Work and acceptance

| Step | Required result | Next action |
| --- | --- | --- |
| Guarded quick survey | Four category/prompt contracts on the same 512 label-free selected development pairs; numerical repeats, truncation audit and durable completion records | Compare broad category, leaf, full hierarchy and hierarchy with product-role instructions |
| Signal selection | Additional accepted labels, accuracy and harmful errors after the retained comparator; matched whole-query differences and class support | Continue a credible signal; retain inconclusive or negative results without declaring a winner |
| Deeper assessment | Completed, numerically verified matched development outputs and a frozen selection rule | Run the four full 6,525-pair passes when the quick survey justifies the reserved cost |
| Calibration, if needed | A separately frozen procedure using the reserved fitting/calibration split; no development or confirmation references enter fitting | Assess one specified recalibration or training change, rather than an unrestricted feature search |
| Actual-gap projection | Eligible residual pairs only, with all stage releases and decisions retained | Report hypothetical additional coverage and cost separately from qualified coverage |
| Confirmation preparation | Complete cascade hash, fresh independent published references and a blinded actual-gap annotation packet | Apply the [confirmation specification](esci-cascade-confirmation.md); missing references or unsupported error bounds remain explicit |

The quick survey's 512 pairs are already exposed development inputs. Its results
help choose the next experiment; they do not independently qualify that choice.
The reserved fresh category cohort contains 400 queries and 6,562 pairs with
references unopened. Its size alone does not establish enough Irrelevant or
accepted Exact support for the required error bounds.

The currently retained comparison has 2,946 published labels among 9,915 pairs.
It needs 4,986 additional qualified labels to reach 80%. The earlier two-stage
projection could reach 48.31% if qualified, leaving 3,142 further labels needed.
Use those residual counts to judge practical value, not standalone model accuracy.

## Decision and delivery

After a useful stage passes independent confirmation, register its immutable
release in MLflow, verify the KServe serving contract and trace the judgement
request. Freeze source-separated judgements for a fresh evaluation of the exact
source commit. Re-run the existing signed gate; do not replace its missing
evidence with an experimental report.

If no measured combination can reach the target, report the remaining coverage,
class-specific error limits and compute cost. Prepare a bounded temporary gate
exception for review, giving I → E protection priority. This batch does not
automatically issue that exception.

Finish the batch on a branch with evidence, an updated roadmap and the next
detailed plan. Open a PR before merging any implementation.
